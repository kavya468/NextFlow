---
title: "Quickstart"
description: "Execute a saved workflow and inspect its results."
---

Create and save a workflow in the editor. A Text-to-Text connection is a useful first check because it requires no paid provider. The application still needs a running Trigger.dev worker.

## Find your workflow

Configure the environment variables described in [authentication](/authentication), then list your workflows:

```bash
curl "$NEXTFLOW_ORIGIN/api/v1/workflows" \
  -H "Authorization: Bearer $NEXTFLOW_API_KEY"
```

Set `WORKFLOW_ID` to a returned ID. Fetch `/api/v1/workflows/$WORKFLOW_ID` to inspect node IDs, labels, and exposed input fields.

## Execute the saved graph

```bash
curl -X POST "$NEXTFLOW_ORIGIN/api/v1/workflows/$WORKFLOW_ID/execute" \
  -H "Authorization: Bearer $NEXTFLOW_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"idempotencyKey":"first-text-run-001"}'
```

The response includes `runId`, `workflowId`, `scope`, `nodeCount`, `estimatedCredits`, and `status`. `estimatedCredits` is the maximum reservation, not the final charge. Reuse the same idempotency key and request body when retrying an uncertain response; use a new key for an intentionally new run.

To supply runtime values, use `inputs` keyed by internal node ID or `variables` for exposed inputs keyed by label. See [execute workflow](/api-reference/workflows/execute) for the payload contract.

## Inspect the result

Set `RUN_ID` to the returned run ID:

```bash
curl "$NEXTFLOW_ORIGIN/api/v1/executions/$RUN_ID" \
  -H "Authorization: Bearer $NEXTFLOW_API_KEY"
```

A completed successful run has status `SUCCESS`. Inspect `nodeRuns[].inputs` and `nodeRuns[].outputs` to verify what each node received and produced. `DISPATCH_UNKNOWN` means the start is unconfirmed; it does not mean the run is safe to repeat with a new key. The editor's recovery action checks uncertain runs without creating another reservation.
