---
title: "Execute Workflow"
openapi: "POST /v1/workflows/{id}/execute"
---

Executes a saved workflow owned by the API-key user. The server validates the graph, captures a revisioned snapshot, and reserves credits before dispatch.

## Runtime inputs

- `inputs` targets internal node IDs, with a map of input field names to values for each node. Fields must satisfy the selected node's contract.
- `variables` targets exposed inputs using the node label. Text, image, and video passthrough values are exposed automatically; other fields must be enabled by the workflow author. Nonmatching exposed labels are ignored.
- `idempotencyKey` identifies one execution request. Reuse it with an identical request after a lost response. A conflicting request with the same key is rejected.

For a text node labeled `Brief`, an exposed override looks like this:

```json
{
  "idempotencyKey": "brief-001",
  "variables": {
    "Brief": { "text": "Describe the product in two sentences." }
  }
}
```

The equivalent node-ID override uses `inputs`:

```json
{
  "idempotencyKey": "brief-002",
  "inputs": {
    "YOUR_TEXT_NODE_ID": { "text": "Describe the product in two sentences." }
  }
}
```

Use IDs and labels from `GET /api/v1/workflows/{id}`. Connected upstream outputs replace saved local values. Explicit runtime overrides are then applied: exposed-label overrides first, node-ID overrides last. Overrides do not bypass failed or missing dependencies.

## Completion callbacks

An optional `webhook.url` receives a best-effort POST containing `event`, `runId`, `status`, and `outputs`. The destination must pass public-network URL validation. Callbacks are not signed and delivery is not retried. The accepted `webhook.events` field is currently not used for filtering. Recovery settlement does not redeliver callbacks; poll the execution endpoint for the authoritative result.

## Response

The response includes `runId`, `workflowId`, `scope`, `nodeCount`, `estimatedCredits`, and `status`. A full run uses scope `FULL`. `estimatedCredits` is the maximum reserved amount; successful usage is settled later and unresolved provider outcomes retain their hold.
