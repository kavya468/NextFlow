---
title: "Get Execution"
openapi: "GET /v1/executions/{id}"
description: "Read the persisted status and node results for a workflow run."
---

Requires the owner's bearer API key. Pass the `runId` returned from an execution request as `id`.

```bash
curl "$NEXTFLOW_ORIGIN/api/v1/executions/$RUN_ID" \
  -H "Authorization: Bearer $NEXTFLOW_API_KEY"
```

The response contains `id`, `status`, `scope`, `nodeRuns`, and an optional `durationMs`.

| Run status | Meaning |
| --- | --- |
| `PENDING` | Accepted and waiting to start |
| `RUNNING` | Worker has claimed execution |
| `DISPATCH_UNKNOWN` | Worker dispatch could not be confirmed |
| `CANCEL_REQUESTED` | Cancellation requested; unresolved work still needs confirmation |
| `SUCCESS` | All admitted nodes succeeded |
| `PARTIAL` | Some nodes succeeded and others failed or were blocked |
| `FAILED` | Execution ended without a successful result |
| `CANCELLED` | Cancellation reached a confirmed final state |

Each node record includes its `nodeId`, `status`, `inputs`, and `outputs` when available. A node marked `BLOCKED` could not run because a dependency failed. An unconfirmed provider outcome can remain `RUNNING` until recovery establishes what happened.

Run scope (`FULL`, `PARTIAL`, or `SINGLE`) describes which nodes were selected; run status describes their outcome. A task stopping at the worker service does not, by itself, prove that the application has recorded the result or settled the reservation.
